## Verified from the docs (used by the implementation)
- Data-deletion callback (VERIFIED, https://developers.facebook.com/docs/development/create-an-app/app-dashboard/data-deletion-callback/): POST with form field `signed_request`; `<sig>.<payload>` base64url; HMAC-SHA256 over the encoded payload with the app secret; payload `algorithm` "HMAC-SHA256", `user_id`, `issued_at`, `expires`; response JSON `{ url, confirmation_code }` where the URL gives a human-readable status; HTTPS only; set in the App Dashboard.
- FLfB dialog: `https://www.facebook.com/<version>/dialog/oauth?client_id&redirect_uri&state&config_id` (`config_id` replaces `scope`); default response type `code`; the redirect carries `code` and the unchanged `state`; cancel returns `error=access_denied&error_reason=user_denied`.
- Code exchange: `GET /<version>/oauth/access_token?client_id&redirect_uri&client_secret&code` -> `access_token`, `token_type`, `expires_in`. Long-lived: `grant_type=fb_exchange_token` (about 60 days). Page tokens obtained from a long-lived user token "do not have an expiration date" but "expire or are invalidated under certain conditions" (conditions not listed: UNVERIFIED).
- Pages: `GET /me/accounts` (token fields seen in the long-lived guide: `access_token`, `name`, `id`, `tasks`); linked Instagram account via the Page fields `instagram_business_account` / `connected_instagram_account`.
- Page subscription: `POST /<page-id>/subscribed_apps` with `subscribed_fields`, `GET` lists, `DELETE` removes (needs `pages_manage_metadata`, `pages_show_list`, a Page token from a user with a task on the Page). **Instagram webhooks cannot be subscribed through `subscribed_fields`: the app dashboard must be used.** App-level callback URL and verify token: dashboard Webhooks product, or `POST /<app-id>/subscriptions` (not for Instagram).
- `debug_token` needs an app access token (`app_id|app_secret`).
- Graph versions: v26.0 is the latest in the versions table, `debug_token` shows v27.0; config default is `v25.0` (documented expiry 2028-07-29), overridable with `META_GRAPH_VERSION`.

## Owner checklist: configure Meta (about 30 minutes, your Meta account only)
Never paste secrets in chat. Everything goes into `/Users/makky/social-crm/.env` (gitignored). `.env.example` lists every variable.
1. **Developer account and app.** developers.facebook.com/apps/creation > app name + contact email > pick the use case(s) the dashboard offers for Messenger/Instagram messaging (exact names UNVERIFIED), or **Other** if none fits > Business step: "I don't want to connect a business portfolio yet" is allowed for creating (a portfolio is required only to access data you do not own) > Go to dashboard. (The create flow has no separate "Business app type" choice; Facebook Login for Business needs a business-type app or a use case that supports it, per Meta.) Under App settings > Basic copy **App ID** and **App Secret** into `.env` as `META_APP_ID`, `META_APP_SECRET`. Add a Privacy Policy URL (any public page for now) and category.
2. **Roles.** App roles > Roles: your own Facebook account is Admin. The Facebook account that manages the test Page must be Admin/Developer/Tester of the app (Development mode only serves people with a role).
3. **Test Page.** Use a Facebook Page you fully control (create a new one if needed). Optional, for Instagram: an Instagram **professional** account linked to that Page (Instagram app > Settings > Messages and story replies > Message controls > Connected tools > **Allow access to messages** ON).
4. **Products.** Add Product > **Facebook Login for Business**; add **Messenger** (and **Instagram** if testing it); add **Webhooks**.
5. **Configuration.** Facebook Login for Business > Configurations > Create: login variation "General", token **User access token**, assets **Pages** (and **Instagram accounts**), permissions: `pages_messaging`, `pages_show_list`, `pages_manage_metadata`, `business_management`, `instagram_basic`, `instagram_manage_messages`. Copy the **Configuration ID** into `.env` as `META_FLFB_CONFIG_ID`. (If the dashboard refuses a permission in Development mode, tell us which; the exact set is UNVERIFIED.)
6. **OAuth redirect.** Nothing to add: in Development Mode Meta allows `http://localhost` redirects automatically (owner-reported). Our redirect URI is `http://localhost:3000/v1/integrations/meta/callback` (`META_OAUTH_REDIRECT_URI`); leave Strict Mode on and do not change other dashboard settings. If R3 shows a redirect error, report the exact message.
7. **Secrets and URLs in `.env`.** `SECRETS_ENCRYPTION_KEY` = output of `openssl rand -base64 32`; `META_VERIFY_TOKEN` = any random string; `BETTER_AUTH_SECRET` = 32+ random characters (the placeholder is too short); `DATABASE_URL_INGEST=postgres://crm_ingest:ingest_dev@127.0.0.1:5436/crm`, `DATABASE_URL_WORKER=postgres://crm_worker:worker_dev@127.0.0.1:5436/crm`.
8. **Start local stack and tunnel.** Test database up (`docker compose -p crmdev up -d --wait`, roles and migrations as in the handoff), then `pnpm --filter @crm/api dev`, `pnpm --filter @crm/web dev`, and `scripts/dev-tunnel/start.sh`. Put the printed URL into `.env` as `META_PUBLIC_BASE_URL` and restart the API.
9. **Webhooks product.** Callback URL `<tunnel>/webhooks/meta/messenger`, Verify token = your `META_VERIFY_TOKEN`, Verify and save. Page object: subscribe fields `messages`, `message_echoes`, `messaging_postbacks`, `message_reads`, `message_deliveries`. For Instagram add `<tunnel>/webhooks/meta/instagram` under the Instagram object and enable `messages` (Instagram fields can only be set here).
10. **App-level callbacks.** App settings > Basic: **Data Deletion Request URL** = `<tunnel>/meta/callbacks/data-deletion`; Facebook Login for Business > Settings: **Deauthorize Callback URL** = `<tunnel>/meta/callbacks/deauthorize`.
11. **Preflight.** `cd apps/api && pnpm exec tsx --env-file-if-exists=../../.env dev/meta-preflight.mts --graph` must end with "All prerequisites present." Then say "ready" and the real test runs per `meta-real-test-runbook.md`.
The tunnel URL changes every start: repeat steps 8 to 10 (callback URLs) each time.
